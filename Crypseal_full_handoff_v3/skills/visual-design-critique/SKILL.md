# visual-design-critique

## When to use
Use to review hierarchy, density, state clarity, trust clarity, and mobile ergonomics before implementation.

## Required process
1. Identify the affected user surface or agent behavior.
2. Gather relevant context from project files, prior decisions, and source-backed specs.
3. Produce concrete edits, not generic advice.
4. Include acceptance criteria and failure cases.
5. If user-facing, include final strings or UI state copy.

## Output contract
- Findings
- Proposed changes
- Acceptance criteria
- Risks / open questions
