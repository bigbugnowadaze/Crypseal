# Tool Protocol

## Design principles

- Typed tools, flat schemas, strict validation.
- The model proposes; app disposes.
- Tool results are machine-readable and human-visible.
- Tool calls are replayable and auditable.
- IDs are generated by app, not trusted from model.

## Tool call envelope

```json
{
  "type": "tool_call",
  "tool": "file.read",
  "args": {
    "path": "src/main.py",
    "reason": "Inspect current implementation before patching."
  }
}
```

## Tool result envelope

```json
{
  "type": "tool_result",
  "tool": "file.read",
  "toolCallId": "app-generated-id",
  "status": "ok",
  "result": {
    "path": "src/main.py",
    "contentPreview": "...",
    "lineCount": 122,
    "sha256": "..."
  }
}
```

## Validation rules

- unknown tool => reject
- missing reason => ask model to repair
- path traversal => reject
- outside project path => approval/escalation or reject
- command chaining => classify high risk
- malformed JSON => repair once, then ask user/model for simpler output
- tool call with app-owned fields such as approvalId/hash => ignore those fields

## Tool schemas

Canonical JSON schemas are in `schemas/tool_protocol.schema.json` and `schemas/events.schema.json`.
